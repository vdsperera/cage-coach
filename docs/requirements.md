## 1. Issues List & Gap Analysis

### Issue 1: Missing Failure Mode for WebGL Context Loss
- **ID:** REQ-ISSUE-001
- **Type:** Missing constraint
- **Location:** `docs/product-brief.md` ("Performance Standard: Stable 60 fps rendering...")
- **Problem:** No specification exists for how the application responds when the mobile or desktop GPU context is lost or unsupported.
- **Question:** How should the UI respond if WebGL is unavailable or fails to initialize?
- **Suggested fix:** If WebGL fails to initialize or `webglcontextlost` fires, display a friendly non-blocking warning banner with instructions to enable hardware acceleration.

### Issue 2: Audio Synthesis Autoplay Permissions
- **ID:** REQ-ISSUE-002
- **Type:** Hidden assumption
- **Location:** `docs/product-brief.md` ("Interactive Audio-Visual Drill Trainer: ... oscillator audio metronome ticks, synthesized speech callouts")
- **Problem:** Browsers block Web Audio API and SpeechSynthesis until explicit user interaction, which will cause drill audio to fail silently if triggered automatically.
- **Question:** What user action unblocks audio, and what is the visual fallback if speech synthesis is unavailable on the device?
- **Suggested fix:** Initialize the `AudioContext` only on the first user interaction (clicking "Start Drill" or clicking the canvas), and provide large on-screen visual banners if speech synthesis is disabled or unsupported.

### Issue 3: Stance Mirroring Coordinate Precision for Grappling Manoeuvres
- **ID:** REQ-ISSUE-003
- **Type:** Ambiguity
- **Location:** `docs/product-brief.md` ("Parametric keyframe interpolation with automatic Orthodox / Southpaw horizontal symmetry mirroring")
- **Problem:** Grappling techniques (e.g. Hip Toss, Armbar) involve two intertwined bodies whose relative contact coordinates may become distorted when mirrored independently.
- **Question:** Does Southpaw stance mirror both Fighter A and Fighter B, or only Fighter A?
- **Suggested fix:** Clarify that in Southpaw mode, the entire scene-relative bilateral coordinate space is mirrored horizontally across the X-axis for both fighters simultaneously to preserve anatomical and spatial contact.

### Issue 4: Local Storage Data Limit & Sanitization Policy
- **ID:** REQ-ISSUE-004
- **Type:** Gap
- **Location:** `docs/product-brief.md` ("Local-First Notes Persistence: Autosaving user study cues with single-click JSON export")
- **Problem:** No maximum character length, storage quota check, or sanitization rules were specified for user notes.
- **Question:** What is the maximum note length per technique and how are quota overflows handled?
- **Suggested fix:** Enforce a 10,000-character cap per technique note, sanitize input against raw HTML injection, and warn the user if storage is unavailable.

## 2. Refined Requirements

### 2.1 Functional Requirements

#### FR-01: 3D Octagonal Cage Arena & Environment `[REFINED]`
* The system shall render an octagonal combat arena mat of radius 4.6 m with mat height 0.08 m, center canvas ring (1.4 m radius), 8 steel posts, vinyl protective padding, and transparent diamond chain-link fence mesh.
* The environment shall include dual-tier lighting: a 0.75-intensity sky/ground hemisphere ambient light and a directional sun light casting soft PCF shadows (`bias: -0.0015`).

#### FR-02: Procedural Kinematic Humanoid Rigging `[REFINED]`
* The system shall construct two procedural "clay" humanoid figures (Fighter A with red accent `#D9442F`, Fighter B with blue accent `#3F7FD6`) composed of geometric primitives (`CylinderGeometry`, `SphereGeometry`, `BoxGeometry`).
* The skeletal hierarchy shall track 15 articulable joints: `root`, `spine`, `head`, `lSh`, `lEl`, `lWrist`, `rSh`, `rEl`, `rWrist`, `lHip`, `lKnee`, `lAnkle`, `rHip`, `rKnee`, `rAnkle`.
* Shoulders and hips shall rotate strictly in `YXZ` Euler order to prevent gimbal lock during rotational strikes; all other joints shall rotate in `XYZ` order.

#### FR-03: Deterministic Stance Inversion (Orthodox & Southpaw) `[REFINED]`
* The system shall allow instantaneous toggling between Orthodox (default) and Southpaw stances via UI button or the `A` hotkey.
* In Southpaw stance, the system shall mirror spatial translations (`pos.x = -pos.x`) and negate angular rotation vectors around the Y and Z axes while swapping contralateral limb pairs (`lSh <-> rSh`, `lHip <-> rHip`, etc.).

#### FR-04: Curated Technique Knowledge Base `[REFINED]`
* The system shall provide access to 24 predefined martial arts techniques partitioned into three categories:
  1. **Striking (10):** Jab (`1`), Cross (`2`), Lead Hook (`3`), Rear Uppercut (`4`), Lead Elbow (`5`), Rear Knee (`6`), Teep (`7`), Rear Roundhouse (`8`), Outside Slip (`9`), Leg Check (`0`).
  2. **Grappling & Takedowns (8):** Collar Tie (`Q`), Double Leg (`W`), Single Leg (`E`), Hip Toss (`R`), Sprawl (`T`), Mount (`Y`), Closed Guard (`U`), Side Control (`I`), Rear Naked Choke (`O`), Armbar (`P`).
  3. **Combinations (6):** Jab-Cross (`Z`), Jab-Cross-Hook (`X`), Teep-Cross (`N`), Clinch-Knee (`H`), Double-Mount (`J`), Cross-Hook-Knee (`K`).
* Each technique shall define normalized duration (`dur`), keyframe timeline arrays for both fighters, phase milestones, contact marks, coaching cues, and partner reaction descriptions.

#### FR-05: Real-Time Biomechanical Telemetry Readouts `[REFINED]`
* The system shall compute real-time joint angles and spatial clearances every 3 animation frames:
  - Lead knee flexion angle (degrees)
  - Rear knee flexion angle (degrees)
  - Lead elbow extension angle (degrees)
  - Rear elbow extension angle (degrees)
  - Hip pelvic rotation angle (yaw in degrees relative to the opponent)
  - Torso lean angle (degrees deviation from vertical + forward/backward vector)
  - Head vertical height above mat (meters)
  - Lead hand vertical height above mat (meters)
* Computations must operate on pre-allocated scratch vectors without allocating objects on the JS heap.

#### FR-06: Dynamic 3D Visual Guidance & Annotations `[REFINED]`
* **Contact Rings & Labels:** Dynamic billboard sprites shall pulse and display at anatomical impact points during active contact windows.
* **Rotational Arcs:** 3D extruded tube arcs (`CatmullRomCurve3`) shall display pelvic and shoulder rotational degrees when rotation exceeds 12°.
* **Footprints:** Mat target stamps shall indicate initial stance and peak impact foot placement.
* **Ghost Clones:** Up to 8 semi-transparent ghost clones shall display keyframe milestone poses with phase name labels.
* **Strike Trail:** A dynamic buffer geometry line shall trace the endpoint of active striking limbs.

#### FR-07: Interactive Audio-Visual Drill Coach `[REFINED]`
* The system shall provide an automated drill coach running an internal state machine: `idle` -> `wait` -> `perform` -> `show` -> `wait`.
* The drill shall prompt a random technique from a selectable pool (Striking, Grappling, Combos, All) at user-selected intervals (3 s, 5 s, 8 s).
* Audio prompts shall trigger an 880 Hz oscillator tick and Web Speech synthesis voice announcement on callout, followed by a 440 Hz tick when the visual reference begins.
* A high-contrast on-screen banner (`#callout`) shall display the technique name and shortcut key.

#### FR-08: Local-First User Notes & JSON Export `[REFINED]`
* The system shall allow users to record custom coaching cues and training notes per technique.
* Notes shall be auto-saved to `localStorage['cagecraft3d-notes']` with a 400 ms debounce, capped at 10,000 characters per technique.
* The system shall provide an "Export all notes" button that compiles all stored notes into a downloadable `cagecraft-notes.json` file.

#### FR-09: Multi-Camera Viewports & Quad-Split Scissor Rendering `[REFINED]`
* The system shall support 5 camera viewing modes: Front (0), Side (1), Above (2), Behind (3), and Partner's Eyes POV (4).
* The system shall support a Quad-Split Viewport mode (`V` key) rendering 4 simultaneous perspective viewpoints (Main Orbit view at 62% width, plus 3 stacked side/top/rear views at 38% width) using WebGL scissor testing.

#### FR-10: Optional External Motion Capture Loading `[NEEDS CLARIFICATION]`
* If a `clips.json` manifest is present in the working directory, the system shall dynamically load FBX/GLTF loaders and retarget skeletal animation to skinned characters.
* *Assumption for current milestone:* In the absence of `clips.json`, the system runs purely on procedural "clay" kinematics without throwing network errors or blocking execution.

### 2.2 Non-Functional Requirements

#### NFR-01: Performance & Zero-Allocation Hot Path `[REFINED]`
* The 3D render loop (`frame()`) and telemetry ticker (`updateReadouts()`) must achieve a consistent 60 frames per second on standard hardware (16.6 ms per frame budget).
* Zero heap objects (`Vector3`, `Euler`, `CanvasTexture`, arrays) may be allocated inside `requestAnimationFrame`.

#### NFR-02: Zero-Network Offline Reliability `[REFINED]`
* The core application must function completely offline without internet connectivity once loaded.
* Dynamic textures for annotations and markers must be cached in memory (`labelTexCache`, `sharedRingTex`) to eliminate redundant GPU uploads.

#### NFR-03: Responsive & Mobile Touch Ergonomics `[REFINED]`
* The layout must adapt gracefully across viewports from 320 px (mobile) to 4K displays.
* On screens under 760 px, UI cards shall dock cleanly at the bottom without obscuring center-stage martial arts action.
* The canvas shall have `touch-action: none` to ensure mobile orbit controls do not trigger default browser pinch-zoom.

#### NFR-04: Data Privacy & Storage Safety `[REFINED]`
* No user data, telemetry, or training notes shall be transmitted to external servers.
* `localStorage` read and write operations must be wrapped in defensive try/catch blocks with graceful session memory fallback.
