## 2. User Stories

### US-001: Inspect Technique in 3D Space
* **Statement:** As a combat sports practitioner, I want to orbit, pan, and zoom around a 3D martial artist in an octagonal cage, so that I can observe strike trajectories from angles impossible in 2D video.
* **Priority:** Must have — Foundational capability of the application.
* **Assumptions:** Browser supports WebGL 1.0 or 2.0 with hardware acceleration.
* **Out of scope:** VR head tracking; customizing cage dimensions.
* **Acceptance Criteria:**
  ```gherkin
  Scenario: Orbit camera around active technique (Happy path)
    Given the 3D viewer is loaded on the screen
    When the practitioner drags the mouse pointer or swipes on the canvas
    Then the orbital camera rotates smoothly around the fighter
    And the azimuth and elevation update without jitter.

  Scenario: Zoom camera to inspect foot placement (Happy path)
    Given the 3D viewer is loaded
    When the practitioner scrolls the mouse wheel or pinches on mobile
    Then the camera focal distance smoothly zooms between 2.2 meters and 9.0 meters
    And does not penetrate the mat floor below -0.04 meters.

  Scenario: WebGL context loss (Sad path)
    Given the application is running
    When the underlying WebGL context is lost by the browser GPU
    Then the application does not crash with an uncaught exception
    And an informative notice appears prompting the user to refresh the page.

  Scenario: Boundary zoom clamp (Edge case)
    Given the camera is at its minimum zoom distance of 2.2 meters
    When the practitioner continues scrolling inward
    Then the camera distance remains strictly clamped at 2.2 meters.
  ```

### US-002: Mirror Technique for Southpaw Stance
* **Statement:** As a southpaw fighter, I want to invert the entire technique coordinate system to a left-handed stance with one keystroke, so that I can study techniques in my natural stance without mentally flipping the image.
* **Priority:** Must have — Core value proposition for left-handed combatants.
* **Assumptions:** Technique keyframes are authored in orthodox stance.
* **Out of scope:** Custom stance angles (e.g. Philly shell or square stance).
* **Acceptance Criteria:**
  ```gherkin
  Scenario: Toggle from Orthodox to Southpaw stance (Happy path)
    Given the fighter is currently displayed in Orthodox stance
    When the practitioner presses the "A" key or clicks the "Southpaw" button
    Then the fighter's right hand and right foot become the lead side at positive X
    And the telemetry readouts update to track the right knee and right elbow as lead.

  Scenario: Revert from Southpaw to Orthodox stance (Happy path)
    Given the fighter is currently displayed in Southpaw stance
    When the practitioner presses the "A" key again
    Then the fighter instantly returns to standard Orthodox alignment with left lead.

  Scenario: Rapid stance toggling during continuous playback (Edge case)
    Given a technique animation is playing at 1x speed
    When the practitioner toggles the "A" key 5 times within one second
    Then the animation timeline position "t" continues smoothly
    And no coordinate NaN or deformed bone transforms occur.
  ```

### US-003: Step Through Critical Technique Phases
* **Statement:** As an MMA student, I want to step forwards and backwards between defined keyframe phases (e.g. Chamber, Impact, Retract), so that I can dissect the exact body mechanics at the moment of impact.
* **Priority:** Must have — Core instructional functionality.
* **Assumptions:** Every technique in the knowledge base has defined phase timestamps.
* **Out of scope:** Scrubbing individual sub-frame micro-ticks.
* **Acceptance Criteria:**
  ```gherkin
  Scenario: Advance to next technique phase (Happy path)
    Given the technique animation is paused at Phase 1 ("Extend")
    When the practitioner presses "Enter" or clicks "Next phase"
    Then the playback progress advances immediately to Phase 2 ("Impact")
    And the phase explanation card updates with the corresponding coaching text.

  Scenario: Step backward to previous phase (Happy path)
    Given the technique animation is at Phase 2 ("Impact")
    When the practitioner presses "Backspace" or clicks "Back"
    Then the animation returns to Phase 1 ("Extend")
    And the progress bar indicator reflects the previous phase interval.

  Scenario: Stepping backward from the first phase (Edge case)
    Given the animation is at the start (t = 0.0) of Phase 1
    When the practitioner presses "Backspace"
    Then the animation remains at t = 0.0 and does not wrap to negative time.
  ```

### US-004: Monitor Real-Time Joint Telemetry Readouts
* **Statement:** As a combat sports coach, I want to observe numerical joint angles (lead knee bend, elbow extension, hip rotation, torso lean) updated in real time, so that I can verify whether the athlete is achieving proper extension and weight transfer.
* **Priority:** Must have — Differentiating analytical feature.
* **Assumptions:** Anatomical landmarks are mapped to skeletal joints.
* **Out of scope:** Automated scoring of user video.
* **Acceptance Criteria:**
  ```gherkin
  Scenario: Live knee and elbow angle updates (Happy path)
    Given a strike (e.g. Cross) is executing
    When the arm extends to full impact
    Then the rear elbow angle displays between 170° and 180°
    And the lead knee bend displays its current flexion in degrees.

  Scenario: Hip rotation yaw readout (Happy path)
    Given a rear roundhouse kick is executing
    When the fighter pivots their hips across the target line
    Then the "Hip turn" readout displays the angular rotation in degrees.

  Scenario: Missing or occluded joint marker (Sad path)
    Given an animation state where a joint marker position cannot be computed
    When the telemetry tick executes
    Then the affected readout gracefully displays an em-dash ("–")
    And does not throw a JavaScript error or crash the UI.
  ```

### US-005: Train with Automated Audio-Visual Drill Coach
* **Statement:** As a solo athlete, I want an automated drill coach to call out random techniques with audio beeps and voice prompts, so that I can drill my physical reactions before the reference animation displays.
* **Priority:** Must have — Essential for solo mat practice.
* **Assumptions:** Browser has audio playback and Web Speech synthesis capabilities.
* **Out of scope:** Voice recognition of user responses.
* **Acceptance Criteria:**
  ```gherkin
  Scenario: Callout phase triggers audio and visual prompt (Happy path)
    Given Drill Mode is activated with a 5-second gap on the "Striking" pool
    When the drill state enters "wait" completion
    Then an 880 Hz metronome tone sounds
    And the technique name is spoken via speech synthesis
    And an oversized visual callout banner displays the technique name and hotkey.

  Scenario: Reference replay executes after reaction window (Happy path)
    Given a callout banner is visible during the reaction window
    When the reaction window completes
    Then a 440 Hz confirmation tone sounds
    And the 3D model performs the requested technique at current speed
    And pauses at peak extension before resetting for the next call.

  Scenario: Audio blocked by browser autoplay policy (Sad path)
    Given the user has not yet interacted with the webpage
    When Drill Mode is triggered programmatically
    Then the audio tone fails gracefully without an uncaught exception
    And the visual callout banner displays normally.

  Scenario: Stop Drill Mode cleanly (Edge case)
    Given Drill Mode is actively running
    When the practitioner presses "D" or toggles off the drill button
    Then the callout banner hides immediately
    And speech synthesis is canceled
    And normal interactive playback resumes.
  ```

### US-006: View Contact Points, Strike Trails, and Rotation Arcs
* **Statement:** As a visual learner, I want to see dynamic 3D contact rings, striking path trails, and rotational angle arcs overlaid on the fighter, so that I can visualize the kinetic chain of force.
* **Priority:** Should have — High-impact educational overlay.
* **Assumptions:** Guides toggle (`state.guides`) is enabled.
* **Out of scope:** Biomechanical stress analysis (MPa/force vectors).
* **Acceptance Criteria:**
  ```gherkin
  Scenario: Contact mark displays at impact timing (Happy path)
    Given a Jab technique is playing
    When normalized playback time reaches the impact window (t = 0.32 to 0.45)
    Then a pulsing golden ring and "Contact: chin" billboard label appear at the left glove
    And disappear cleanly when the hand retracts.

  Scenario: Hip rotation arc displays during high-rotation strikes (Happy path)
    Given a Rear Roundhouse kick is playing
    When the hips turn more than 12 degrees
    Then an extruded golden 3D tube with an arrow cone and degree label appears around the pelvis.

  Scenario: Toggling guides off (Edge case)
    Given guides are visible
    When the practitioner presses "F" or clicks "Guides"
    Then all rings, labels, arcs, and footprints are immediately hidden from the scene.
  ```

### US-007: Inspect Dual-Fighter Grappling and Counters
* **Statement:** As a BJJ/MMA practitioner, I want to view grappling techniques (such as Double Leg or Armbar) with both fighters visible, so that I can understand leverage points and defensive reactions.
* **Priority:** Should have — Essential for multi-body grappling techniques.
* **Assumptions:** Grappling techniques define keyframe tracks for both Fighter A and Fighter B.
* **Out of scope:** Dynamic physics-based ragdoll collisions.
* **Acceptance Criteria:**
  ```gherkin
  Scenario: Grappling technique automatically forces partner visible (Happy path)
    Given the viewer is in "Single" mode (partner hidden for strikes)
    When the practitioner selects a grappling technique (e.g. "Armbar" via "P")
    Then Fighter B (blue accent) is automatically displayed in the scene
    And the partner note displays "Partner taps".

  Scenario: Toggling sparring partner for striking strikes (Happy path)
    Given a striking technique (e.g. Jab) is selected in Single mode
    When the practitioner presses "Tab"
    Then Fighter B appears facing Fighter A and reacts with a head-snap upon impact.
  ```

### US-008: Multi-Angle Quad-Split Scissor Viewports
* **Statement:** As an advanced coach, I want to view the fighter from four camera perspectives simultaneously in a quad-split layout, so that I can evaluate lateral stance and overhead alignment in a single glance.
* **Priority:** Should have — Professional-grade analysis tool.
* **Assumptions:** WebGL context supports scissor testing.
* **Out of scope:** Independent timeline playback per viewport.
* **Acceptance Criteria:**
  ```gherkin
  Scenario: Activate Quad-Split viewport mode (Happy path)
    Given the viewer is in single fullscreen view
    When the practitioner presses "V" or toggles "Split"
    Then the screen divides into a 62% primary Orbit view and 3 stacked side/top/behind views
    And viewport labels ("Orbit", "Side", "Top", "Behind") appear in their respective viewports.

  Scenario: Window resize during split-screen mode (Edge case)
    Given split-screen mode is active
    When the browser window is resized
    Then all four viewports recalculate their scissor rectangles proportionally without distortion.
  ```

### US-009: Record and Export Personal Technique Notes
* **Statement:** As a student, I want to jot down my coach's personal cues for each technique and export them as a JSON file, so that I can keep a private training log that persists across sessions.
* **Priority:** Should have — Personalization and retention feature.
* **Assumptions:** LocalStorage is enabled in the browser.
* **Out of scope:** Cloud sync; social sharing.
* **Acceptance Criteria:**
  ```gherkin
  Scenario: Auto-save notes per technique (Happy path)
    Given the practitioner is viewing the "Cross" technique
    When they type "Turn rear heel fully out" into the notes textarea
    Then after 400 ms of inactivity, the note is saved to localStorage
    And the status indicator displays "Saved".

  Scenario: Export all notes as a JSON file (Happy path)
    Given the practitioner has saved notes across 3 different techniques
    When they click "Export all notes"
    Then the browser downloads a formatted "cagecraft-notes.json" file
    And the file contains key-value pairs mapping technique names to notes.

  Scenario: LocalStorage disabled or quota exceeded (Sad path)
    Given the browser is operating in private browsing with storage disabled
    When the practitioner enters notes
    Then the note is retained in memory for the current session
    And the status displays "Kept for this session only".

  Scenario: Note text length limit (Security / Boundary)
    Given the practitioner pastes a 50,000-character document into notes
    When the save triggers
    Then the note is truncated cleanly to the maximum limit of 10,000 characters
    And does not cause a localStorage quota crash.
  ```

### US-010: Offline Fallback & Graceful Degradation
* **Statement:** As a fighter practicing in a basement gym with no cellular reception, I want the application to load and function fully offline, so that I can train without internet access.
* **Priority:** Could have — Robustness and accessibility.
* **Assumptions:** Application HTML has been opened locally or cached.
* **Out of scope:** Real-time online multiplayer.
* **Acceptance Criteria:**
  ```gherkin
  Scenario: Full offline execution of procedural 3D model (Happy path)
    Given the device is disconnected from the internet
    When the practitioner opens the application
    Then all 24 procedural clay techniques render, step, and drill at 60 fps.

  Scenario: Mocap manifest missing (Sad path)
    Given the device is offline and no "clips.json" file exists
    When the application initializes
    Then it remains in procedural "Clay" mode
    And the "Mocap" toggle button is disabled with an explanatory tooltip.
  ```
